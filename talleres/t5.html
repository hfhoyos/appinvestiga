Actúa como desarrollador frontend y experto en metodología de la investigación en el contexto de la Formación Profesional Integral del SENA. Construye un artefacto monolítico HTML, CSS y JavaScript vanilla, responsivo, llamado «Validador iterativo de preguntas de investigación». (A) INTERFAZ: En la parte superior incluye un textbox tipo password para ingresar manualmente una API Key de OpenAI. Nunca escribas la clave dentro del HTML, CSS o JavaScript ni la incluyas en ejemplos. Debajo, un textarea para la pregunta de investigación; un textbox numérico para establecer una meta de congruencia entre 1 y 100 (por defecto 90%); un indicador visual de progreso entre 0 y 100%; botones Evaluar, Usar versión sugerida y Reiniciar; un panel de recomendaciones y un historial de iteraciones. (B) EVALUACIÓN: Utiliza nueve criterios: claridad, especificidad, delimitación, variables o constructos, operacionalizabilidad, viabilidad, relevancia, supuestos y sesgos, y tipo de pregunta. Solicita a la IA una puntuación entera de 0 a 100 por criterio, una justificación, fortalezas, problemas, recomendaciones y una versión mejorada. Calcula en JavaScript el promedio de los nueve criterios para obtener la congruencia global. Aclara que es una valoración orientativa, no una medida científica validada. (C) ITERACIÓN: El usuario puede reformular y volver a evaluar su pregunta tantas veces como desee. Muestra el historial con fecha, pregunta y puntuación, y una comparación de avances. Indica cuando se alcanza la meta, sin impedir nuevas evaluaciones. Permite incorporar la versión sugerida al textarea para editarla antes de la siguiente consulta. (D) API Y SEGURIDAD: Incluye un modo de simulación sin API Key y un modo de consulta real a OpenAI. En el modo real usa un modelo compatible con chat completions y procesa una respuesta JSON estructurada, validando su contenido y gestionando errores. No guardes la API Key en localStorage, sessionStorage, cookies ni archivos. Advierte explícitamente que introducir la clave en el navegador NO la protege frente a inspección de red o scripts y que para un uso real debe emplearse un backend intermediario que almacene la clave como secreto. No pidas al usuario pegar su clave en la conversación con la LLM. (E) EXPERIENCIA: Diseño accesible y adaptable a móviles, etiquetas claras, estados de carga, mensajes de error, exportación de historial sin credenciales y datos ilustrativos claramente identificados. La simulación no debe presentarse como una evaluación real. Entrega el archivo HTML completo listo para guardar y abrir en un navegador.
Reflexión final: ¿por qué una clave ingresada en un textbox sigue siendo visible para el navegador? ¿Qué cambia cuando un backend intermediario guarda la clave como secreto?
